Documentation for monitor_and_rsync_db_filestores.sh

(generated by ChatGPT, 20/10/2025)

Parses /var/www/html/HEURIST/heuristConfigIni.php to read the existing $remoteServers mapping (no duplication in Bash).

Treats a directory as a “remote DB” only if its name starts with <IDENT>- where <IDENT> is a key from $remoteServers.

Strips the prefix on the destination (IDENT-MyDB → MyDB) and chooses the correct remote host/SSH user/port/key from the PHP config.

Runs on a cron eg. every 5 minutes, detects changes cheaply (find -newer marker), then rsyncs immediately.

Includes retry with exponential backoff, per-identifier bandwidth caps, an overlap lock, and daily logs + summary JSON.

Assumptions: php CLI is available on the server; $remoteServers in heuristConfigIni.php contains at least server and sshuser (or you accept the defaults below). The DB fields (port, dbuser, dbpass) are ignored for rsync.


Install:

sudo install -m 0755 -o dbtunnel -g dbtunnel monitor_and_rsync_db_filestores.sh /srv/scripts/monitor_and_rsync_db_filestores.sh
sudo mkdir -p /var/lib/heurist-sync/state /var/log/heurist-sync /var/run
sudo chown -R dbtunnel:dbtunnel /var/lib/heurist-sync /var/log/heurist-sync

Cron: 
*/5 * * * * /srv/scripts/monitor_and_rsync_db_filestores.sh >/dev/null 2>&1

Notes / tuning

No hard-coded servers. The script only trusts identifiers from $remoteServers in heuristConfigIni.php. Identifiers can be any string (mixed case, underscores, digits, etc.) except they must not include - because - is the delimiter.

Defaults: If an entry lacks sshuser, sshport, or sshkey, the script uses:

sshuser=$DEFAULT_SSHUSER (default dbtunnel)

sshport=$DEFAULT_SSHPORT (default 22)

sshkey=$DEFAULT_SSHKEY (default /home/dbtunnel/.ssh/id_ed25519)
You can override these via environment vars.

Bandwidth caps per identifier: set environment variables like:

export BW_LIMIT_HN=12000
export BW_LIMIT_HEURIST_AU=6000


Excludes: e.g. EXCLUDES="thumbnails/**,cache/**,tmp/**".

Retries/backoff: MAX_RETRIES=4, BACKOFF_BASE_SEC=8 → 8/16/32s backoffs.

Behaviour summary

Every run checks for modified files; successful rsyncs touch their marker.

Any failure after all retries adds that directory to FAILED_DIRS.

At the end of the run, if FAILED_DIRS is non-empty, an email is sent listing them and appending the last 20 log lines.

Works seamlessly with your central heuristConfigIni.php; no redundancy.

Mail sending is optional: if the mail command isn’t available, the script logs a warning instead of aborting.
