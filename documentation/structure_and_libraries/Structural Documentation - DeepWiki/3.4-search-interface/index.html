This document covers Heurist's comprehensive search and filtering systems, including faceted search interfaces, advanced query builders, saved search management, and their integration with the backend search engine. For information about record viewing and display after search results are returned, see Record Viewing. For details about importing and manipulating search results, see Batch Operations.

Search System Architecture

Heurist's search interface provides multiple levels of search functionality, from simple text queries to complex multi-criteria searches with relationship traversal. The system consists of frontend widgets for query construction and a sophisticated backend query processing pipeline.

Core Search Components

Faceted Search Widget (search_faceted)

The search_faceted widget is the primary interface for drill-down searching using predefined facets. It allows users to progressively narrow their search by selecting values from various field-based filters.

The faceted search system operates through several key phases:

Initialization Phase: hclient/widgets/search/search_faceted.js600-727

  • _initFacetQueries() converts field codes to Heurist queries
  • Creates both main search queries and individual facet value queries
  • Handles complex hierarchical relationships between record types

Search Execution: hclient/widgets/search/search_faceted.js2600-2800

  • doSearch() executes the main query with current facet selections
  • _fillQueryWithValues() incorporates user-selected facet values
  • Supports spatial and additional text filtering

Facet Recalculation: hclient/widgets/search/search_faceted.js3800-4200

  • _recalculateFacets() updates available facet values based on current results
  • _redrawFacets() refreshes the UI with new counts and options
  • Handles progressive disclosure and pagination of facet values

Sources: hclient/widgets/search/search_faceted.js600-727 hclient/widgets/search/search_faceted.js2600-2800 hclient/widgets/search/search_faceted.js3800-4200

Advanced Query Builder (searchBuilder)

The searchBuilder widget provides a sophisticated interface for constructing complex database queries using a visual field-by-field approach. It generates Heurist JSON query structures that are processed by the backend query engine.

searchBuilder Widget Structure

Query Building Process: hclient/widgets/search/searchBuilder.js518-620

  • addFieldItem() creates searchBuilderItem widgets for individual search criteria
  • Each item handles field selection, comparison operators, and value inputs
  • select_main_rectype determines available fields through database structure analysis

Field Tree Integration: hclient/widgets/search/searchBuilder.js397-415

  • showFieldSelector() displays hierarchical field selection interface
  • pnl_Tree shows related record types and their fields
  • Supports complex relationship traversal and reverse relationships

Query Composition: hclient/widgets/search/searchBuilder.js332-388

  • _doCompose() builds JSON query structure from widget state
  • adjustDimension() manages widget layout based on number of criteria
  • Integrates conjunction operators, sorting, and ruleset expansion

Sources: hclient/widgets/search/searchBuilder.js518-620 hclient/widgets/search/searchBuilder.js397-415 hclient/widgets/search/searchBuilder.js332-388

Search Criteria Widget (searchBuilderItem)

The searchBuilderItem widget represents individual search criteria within the searchBuilder. It handles field-specific input types, comparison operators, and value validation.

searchBuilderItem Components

Field Type Handling: hclient/widgets/search/searchBuilderItem.js351-626

  • _defineInputElement() configures input widgets based on field data type
  • Supports all Heurist field types with appropriate comparison operators
  • Dynamically loads enumeration values and resource constraints

Operator Configuration: hclient/widgets/search/searchBuilderItem.js514-626

  • Different comparison operators based on field type (text matching, numeric ranges, date comparisons)
  • Special operators for existence checks (any, NULL) and value counting
  • Supports negation and complex text search modes

Value Input Integration: hclient/widgets/search/searchBuilderItem.js396-467

  • Uses editing_input widgets for consistent value input handling
  • Supports multi-value fields with conjunction operators
  • Handles field-specific validation and formatting

Backend Query Processing

Query Composition Engine (composeSql.php)

The backend query processing translates frontend Heurist queries into optimized SQL statements. The composeSql.php module handles this transformation through a sophisticated parsing and compilation system.

Query Processing Pipeline

Query Parsing: hserv/records/search/composeSql.php291-463

  • parse_query_to_json() converts plain text queries to structured JSON format
  • Handles both simple keyword queries and complex hierarchical structures
  • Supports nested subqueries and relationship expressions

SQL Compilation: hserv/records/search/composeSql.php516-630

  • get_sql_query_clauses_NEW() orchestrates the full compilation process
  • HQuery class manages query tree construction and SQL generation
  • Handles user permissions, search domains, and visibility constraints

Query Tree Classes: hserv/records/search/composeSql.php641-850

  • HQuery represents complete search queries with sorting and domains
  • HLimb handles logical operations (AND/OR) between predicates
  • HPredicate processes individual field searches and relationships

Sources: hserv/records/search/composeSql.php291-463 hserv/records/search/composeSql.php516-630 hserv/records/search/composeSql.php641-850

Relationship Query Builder

Rule Builder (ruleBuilder)

The ruleBuilder widget enables construction of complex relationship-based search expansions that follow pointer fields and relationships to find related records.

ruleBuilder Architecture

Relationship Analysis: hclient/widgets/search/ruleBuilder.js272-350

  • _onSelectRectype() analyzes database structure for available relationship fields
  • Identifies both direct pointer fields and reverse relationships
  • Builds lists of possible target record types for each relationship

Multi-Level Rules: hclient/widgets/search/ruleBuilder.js222-242

  • _addChildRule() creates nested rule levels for complex relationship traversal
  • Supports up to 3 levels of relationship following
  • Each level can have additional filtering criteria

Integration with Search Builder: hclient/widgets/search/ruleBuilder.js186-191

  • _editFilter() opens searchBuilder for additional criteria on target records
  • Rules generate expansion queries that are merged with base search
  • Supports both inclusive and exclusive rule modes
